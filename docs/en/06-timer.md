# 06 · "00 Timer"

[← previous](05-diagnosis-black-screen-ram.md) · [← back](../../README.md) · [alert details and full screen: 06-1 →](06-1timer.md)

## What it is

A fake game ("00 Timer", "zz Timer calibrar") that shows up in the console lists (NES, GBA, etc.) and works as a countdown: pick a time, go back to the menu, play, and when it ends the "TEMPO ACABOU" alert is drawn over the game and the stick says "time's up". The timer works across the whole stick, not per console.

Timer cover art (AI-generated by the author): `assets/timer_covers/` (`gba.png`, `gb.png`, `gbc.png`, `fc.png`, `sfc.png`, `md.png`, `n64.png`, `ps1.png`, `atari.png`, `cps.png`). Per the hypothesis in chapter 02, naming the cover like the fake "game" in the console folder is enough.

## On-device scripts

In `scripts/timer/`:

- **`hook.sh`** (timer version, "update 3", unmodified): if the game name does not contain "Timer", it writes `$1 $2` to `/tmp/gtimer.game` and exits with `exit 1`. If it does, it copies `timer/gtimer` to `/tmp`, runs `chmod +x`, runs it (`cal` when the name has "calibrar") with a 150 s safety kill, and logs `fim rc=...` to `hook.log`.
- **`run.sh <end_uptime>`** (**final version**, details in [06-1](06-1timer.md)): sleeps in steps of up to 20 s until `uptime` reaches the end moment; **freezes RetroArch** (`kill -STOP`) **before** starting `gtimer alarm`; writes the duration (`DUR=15`) to `timer/aviso.txt`; plays `timer/v/acabou.wav` twice; listens to every `/dev/input/event*` with `evtest` and **kills `gtimer` on any button**; at the end (or on any error, through `trap`) **resumes the game** (`kill -CONT`). Settings at the top of the file: `DUR` and `PAUSAR`. The previous version (sleep, `gtimer alarm`, `aplay` twice) is in the git history.
- **`gtimer`**: ARM ELF binary of ~400 KB, **no source and not included** here. From its strings and disassembly **[measured]**: it takes `alarm` (draws the alert), `cal` (button calibration), `test`, or no argument (screen to set the minutes). It opens **no input device** itself (button handling is done by `run.sh` with `evtest`) and reads the alert length from `/sdcard/timer/aviso.txt` (1 to 3599 s; 30 s without the file). `gtimer` is probably what calls `run.sh` **[inferred]**.

### ⚠️ Conflict to resolve before installing `hook.sh`

The `hook.sh` in this folder is the **timer version**. The one used for GBA games (ch. 04) launches RetroArch with `gbx_mod.cfg` through `ra_wrap.sh`. For non-Timer games the "update 3" version does `exit 1`, which **probably hands launching back to the stick's default path, without `gbx_mod.cfg`** (you would lose fast-forward) **[inferred]**. Back up your current `hook.sh` and **merge both versions** (the "Timer" branch from here + the GBA branch from there) before copying. The GBA `hook.sh` will be added to the repo later. (`run.sh` does not have this problem: it can be copied on its own.)

## Alert flicker: fixed

**[inferred from the code and the log, confirmed in practice]** `gtimer` draws into the DRM buffer that is on screen **at the moment it starts** and re-copies its box every 30 ms. RetroArch alternates two buffers, so the box was only visible on frames where the buffer `gtimer` picked was the one being displayed: that was the flicker. The fix is to freeze RetroArch **before** starting `gtimer`, so the visible buffer stays still. After the change the alert stopped flickering.

- The earlier `kill -STOP` test "made things worse" (game froze ~25 s, `dtick=0`, no sound). That freeze is now the **intended** behavior: the game stays paused during the alert and the `trap` guarantees it is resumed **[inferred]** (the old test had no controlled resume and no button to dismiss).
- The rewrite with `evtest` (any button closes the alert) is now applied.
- Known side effects (audio pop on resume, a button pressed during the pause reaching the game, `killall aplay`): see [06-1](06-1timer.md), section 8.

## Timer inside the arcade list: given up

In arcade, the menu only lists what is in `tbl_game` of `games.db` (36 games, `gameid` 1–36; arcade: `mslug`=1, `kof97`=2, files in `game/cps/`). The folder also holds `kof97.fs` (424 B) and `mslug.fs` (480 B), dated 1979, whose purpose is **unknown**.

| Attempt | What changed | Result |
|---|---|---|
| 1 | New row with `gameid` 900 **and** a fake `00 Timer.zip` (actually a GBA ROM) | Menu hung; two changes at once, cause undetermined |
| 2 | Database only: `gameid` 37, row copied from `kof97`, names in `tbl_zh/en/tw/ko`; no `.zip` | Hung again on the loading screen |

An empty `00 Timer.fs` (0 B, created by us) was in the folder; an empty file is unlikely to break the menu, so the DB row is the most likely cause (not proof). Unconfirmed guess: the menu uses `gameid` as a position in a fixed list.

**Decision:** use the timer through the other consoles. The card was restored from `games.db.bak` and cleaned (DB with the original 36 games, no timer row, empty `.fs` removed).

If you ever try again, only with the card plugged into the PC and `games.db.bak` at hand:

```bash
S=/run/media/user/<LABEL>; DB=$S/game/games.db
cp -n "$DB" "$DB.bak"                  # backup BEFORE any change
# restore:
cp "$DB.bak" "$DB" && sync
# check:
sqlite3 -readonly "$DB" "select count(*) from tbl_game; select count(*) from tbl_game where game='00 Timer';"   # 36 and 0
```

### Using the timer with arcade

1. Open "00 Timer" on NES, GBA, etc. and pick the time.
2. Go back to the menu and open `mslug` or `kof97`.
3. At the end, the alert should appear over the game and the stick should say "time's up".
